# EIS 근무시간 위젯

통합경영정보시스템(EIS)의 **근무시간현황** 화면 위에 작은 판을 띄워, 정산기간 잔여 근무시간을
분 단위까지 보여 준다. 매번 표를 눈으로 더할 필요가 없다.

```
달성률 · 출장·휴일 포함   잔여 시간                    오늘 · 09-08
        88%             남은시간         9:58 남음   출근 / 퇴근        08:13 / –
    현재까지 48%         출장·휴일 포함               근무 · 현재까지        38:02
                        현재까지        41:58 남음   출근예정   24:00 (+휴일 8:00)
                        이 중 휴일근무 8:00          기준 근무              80:00
```

## 무엇을 하고, 무엇을 하지 않는가

- **화면에 이미 그려진 숫자만 읽는다.** 서버에 따로 요청하지 않고, 숨은 내부 객체를 뒤지지
  않으며, 트랜잭션을 직접 부르지 않는다. 사람이 눈으로 보는 것과 같은 값을 같은 자리에서 읽을 뿐이다.
- 딱 한 번 **오늘 날짜 행을 클릭**한다. 출퇴근 시각을 얻기 위해서이며, 사람이 하는 클릭과 같다.
  일별 상세가 이미 오늘을 가리키고 있으면 클릭하지 않는다.
- 읽은 값은 **내 브라우저 안에만**(`localStorage`) 남는다. 어디로도 보내지 않는다.
- 주소를 코드에 박아 두지 않았다. 사내 EIS 도메인에 붙는 방식이라, 평소처럼
  포털에서 근무시간현황을 열면 위젯이 알아서 뜬다.

## 설치 — 셋 중 하나만 하면 된다

브라우저를 열어 두는 것이 싫다면 A안(데스크톱 앱), 브라우저 안에서 보는 것으로 충분하다면
B안(크롬 확장)을 고른다. C안(북마클릿)은 확장 등록이 막혀 있을 때의 대안이다.

### A. 데스크톱 앱 (권장 · 브라우저를 열지 않아도 된다)

트레이에 상주하면서 5분마다 EIS를 읽어 오고, 작은 창을 항상 화면 위에 띄운다.
EIS 화면을 여는 일은 앱이 숨은 창에서 대신 처리하므로 브라우저를 켤 필요가 없다.

**쓰는 쪽**이라면 실행파일만 있으면 된다. Node.js도 명령줄도 필요 없다.

1. `dist\EIS 근무시간 위젯-win32-x64` 폴더를 통째로 받아 원하는 자리에 둔다.
2. 그 안의 **`EIS 근무시간 위젯.exe`** 를 실행한다.
3. 처음 켜면 그룹웨어 로그인 창이 뜬다. **로그인한 뒤, 평소처럼 근무시간현황 메뉴까지
   눌러 준다.** 근무시간 화면이 뜨는 순간 창이 스스로 숨고 위젯이 화면에 나타난다.

자세한 사용법과 각 칸이 무엇을 뜻하는지는 [사용설명서](docs/USAGE.md)에 따로 적었다.

**고치는 쪽**이라면 소스에서 바로 띄운다.

```bash
cd desktop
npm install
npm start
```

실행파일을 다시 만들 때는 `npm run package`를 쓴다. 실행 정책에 막히면 `npm.cmd`로
바꾸어 부른다. 산출물은 `dist\`에 만들어진다.

> **패키징이 `EBUSY`로 멈추면 Claude 데스크톱 앱을 먼저 끈다.** 그 앱이 프로젝트 폴더의
> `resources\app.asar`를 붙잡아 둔다 (2026-09-08 Restart Manager로 확인). 잠긴 파일도
> `cp`로는 읽히므로, 당장 배포본이 필요하면 폴더를 다른 자리로 복사한 뒤 그 사본을 압축한다.

> **실행파일과 소스 실행판은 동시에 켤 수 없다.** 같은 앱으로 취급되어 나중에 켠 쪽이
> 조용히 스스로 종료한다 (2026-09-08 실측). 한쪽을 트레이 메뉴의 `종료`로 끄고 다른
> 쪽을 켜야 한다.

> **로그인만으로는 값이 들어오지 않는다.** EIS 쪽 세션은 포털에서 메뉴를 눌러 넘어가는
> 그 동작이 만든다. 주소만 직접 불러서는 세션이 만들어지지 않는다는 것을 2026-09-07에
> 세 번 확인했다. 그래서 앱은 포털에서 기다리기만 하고, 누르는 일은 사람이 한다.

트레이 아이콘을 누르면 다음을 할 수 있다.

| 항목 | 하는 일 |
|------|---------|
| 위젯 창 보이기 | 작은 표시 창을 켜고 끈다 |
| 지금 새로 읽기 | 5분을 기다리지 않고 곧바로 다시 읽는다 |
| EIS 화면 열기 | 숨어 있던 수집 창을 띄운다 (값이 이상할 때 원본을 확인하는 용도) |
| 종료 | 앱을 끝낸다 |

위젯 자체에도 새로고침 단추(`⟳`)와 닫기 단추(`✕`)가 오른쪽 위에 있다.

> **앱을 끄면 로그인 상태가 사라진다.** 그룹웨어와 SSO가 발급하는 쿠키에 만료 시각이
> 없어서, 앱이 종료될 때 함께 없어지기 때문이다 (2026-09-04 실측, 3회 반복 확인).
> 따라서 앱을 켤 때마다 로그인 창이 한 번 뜨고, 그 뒤로는 조용히 돌아간다.

### B. 크롬 확장 (한 번 등록하면 EIS 화면에서 계속 저절로 뜬다)

1. 크롬 주소창에 `chrome://extensions` 를 입력한다. (또는 우측 상단 퍼즐 아이콘 → 확장 프로그램 관리)
2. 화면 오른쪽 위 **개발자 모드**를 켠다.
3. 왼쪽 위 **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 저장소의 `extension` 폴더를 고른다.
4. 끝. EIS 근무시간현황 화면을 열면 오른쪽 위에 위젯이 뜬다.

권한을 하나도 요구하지 않는다. `manifest.json`에 `permissions` 항목 자체가 없고, 접근 범위는
`https://<사내 EIS 도메인>/*` 하나뿐이다.

팀원에게는 `extension` 폴더를 압축해 그대로 전달하면 된다. 받은 사람은 풀어서 3번만 하면 된다.

> **Tampermonkey는 권하지 않는다.** 크롬 138부터 확장별로 "사용자 스크립트 허용" 토글이
> 따로 생겼고 기본이 꺼짐이다. 2026-09-04 크롬 152 환경에서 그 토글을 켠 뒤에도 스크립트가
> 실행되지 않아 원인을 규명하지 못했다. 직접 만든 확장은 일반 content script라서 이 제약을
> 아예 받지 않는다. Tampermonkey를 이미 쓰고 있다면
> [eis-work-widget.user.js](eis-work-widget.user.js)를 그대로 붙여 넣어도 된다.

### C. 북마클릿 (확장 등록이 막혀 있을 때 · 볼 때마다 한 번 누른다)

1. 크롬 북마크바에서 오른쪽 클릭 → **페이지 추가**.
2. **이름**에 `근무시간`, **URL**에 [eis-work-widget.bookmarklet.txt](eis-work-widget.bookmarklet.txt)의
   내용을 통째로 붙여 넣는다. (`javascript:`로 시작하는 아주 긴 한 줄이다.)
3. EIS 근무시간현황 화면에서 그 북마크를 누르면 위젯이 뜬다. 여러 번 눌러도 겹치지 않는다.

> 크롬은 주소창에 직접 `javascript:`를 붙여 넣으면 앞부분을 지운다. 반드시 **북마크의 URL 칸**에 넣어야 한다.

## 쓰는 법

- **끌어서 옮길 수 있다.** 옮긴 자리는 기억된다.
- 오른쪽 위 **×** 로 닫는다. 화면을 새로 고치면 다시 뜬다.
- EIS의 다른 화면으로 가면 마지막으로 읽은 값을 흐리게(테두리가 점선) 띄우고 **"n분 전 값"**을 붙인다.
  근무시간현황 화면으로 돌아오면 다시 실시간이 된다.

## 숫자를 읽는 법

| 표시 | 뜻 |
|---|---|
| **남은시간 (출장·휴일 포함)** | 앞으로의 출근예정과 휴일근무까지 모두 반영한 잔여다. 정산기간이 끝났을 때 최종으로 남을 시간이라고 보면 된다 |
| **현재까지** | 오늘까지 실제로 찍힌 근무만 반영한 잔여다. 앞으로의 예정은 빠져 있다 |
| **이 중 휴일근무** | 위쪽 값에 들어 있는 휴일근무 예정분이다 |

두 값 모두 **파란색이면 아직 채워야 할 시간**이고, **빨간색이면 기준을 넘긴 시간**이다.
숫자 옆에 `남음` 또는 `초과`를 함께 적는다.

왼쪽 칸의 달성률도 같은 기준으로 계산한다. 큰 숫자는 출근예정과 휴일근무까지 모두
더한 값이므로, 그 값이 100%를 넘는 순간 `남은시간`이 `초과`로 바뀐다. 둘은 같은 사실을
다르게 적은 것이다 (2026-09-08 사용자 결정으로 기준을 통일했다).

EIS 화면은 근무시간을 시간 단위로 잘라 보여 준다(예: 잔여 `-12`). 위젯은 같은 화면에 들어 있는
**분 단위 원본**을 읽으므로 `-11:24`처럼 분까지 맞다. 화면의 `-12`는 이 값을 내림한 것이다.

## 값이 안 나오면

**위젯이 아예 안 뜬다면 그게 정상 동작이다.** EIS 화면 구조가 바뀌면 값을 잘못 읽는 대신
아무것도 그리지 않도록 만들었다. 조용히 틀린 숫자를 보여 주는 쪽이 훨씬 위험하기 때문이다.

- 근무시간현황 화면이 맞는지, 표가 다 그려졌는지 먼저 본다 (뜨는 데 1~2초 걸린다).
- 그래도 안 뜨면 EIS 화면이 개편된 것이다. 고쳐야 한다.

## 고칠 때 (개발자용)

**[eis-work-widget.user.js](eis-work-widget.user.js) 하나만 고친다.** 확장과 북마클릿은 거기서 뽑아낸다.

```bash
node build.js && node verify-bookmarklet.js
```

- `build.js` — 유저스크립트 머리말을 떼고 두 산출물을 만든다.
  `extension/widget.js`는 주석까지 그대로 두고(주소창을 거치지 않으므로 줄일 이유가 없다),
  북마클릿은 주석을 떼고 URL 인코딩한다. 문법·인코딩 왕복·핵심 조각 존재를 모두 확인한다.
- `verify-bookmarklet.js` — 뽑아낸 북마클릿을 최소 DOM 스텁 위에서 **실제로 실행해** 본다.
  화면도 캐시도 없을 때 조용한지, 캐시가 있을 때 "n분 전 값" 화면을 값까지 맞게 그리는지 본다.

두 스크립트 모두 통과해야 한다. 실패하면 배포하지 않는다.

`extension/widget.js`는 생성물이므로 직접 고치지 않는다. 파일 첫 줄에도 그렇게 적혀 있다.

## 검증 현황

- 2026-09-04 실측: 정산기간 **1건**(2026-08-30~09-12, 18회차)에서 표시값 전부가 손으로 계산한
  값과 일치했다. 실제 EIS 화면 위에서 셀 좌표 파싱·오늘 행 클릭·계산·렌더링이 끝까지 도는 것을
  확인했고, 크롬 확장으로 설치한 뒤 새로 고침만으로 자동으로 뜨는 것도 확인했다.
- 2026-09-07 실측: 데스크톱 앱으로 같은 정산기간을 네 차례 읽었고, 표시값이 EIS 화면과 맞는 것을
  확인했다. 새로고침 단추와 5분 주기 자동 갱신도 동작했다. 이 과정에서 **오늘 행의 종료시간 칸이
  퇴근 시각이 아니라 조회 시점**임이 드러났다. 6분이 흐르는 동안 그 칸도 6분 뒤로 밀렸고 근무시간도
  정확히 6분 늘었다. 그래서 오늘 행의 퇴근 자리는 비워 둔다.
- **아직 못 본 경우**: 정산기간 첫날처럼 예정 행이 많아 표가 잘리는 기간, 휴일근무가 여러 날 잡힌 경우,
  연장·야간 열이 채워진 경우. 표가 잘렸을 가능성이 있으면 위젯이 **"출근예정이 더 있을 수 있음"**을 띄운다.
