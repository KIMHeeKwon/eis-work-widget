# EIS 근무시간 위젯 — 사용설명서

통합경영정보시스템(EIS)의 **근무시간현황** 화면을 매번 열지 않고도, 정산기간에 남은
근무시간을 분 단위까지 확인하기 위한 작은 도구입니다. 화면 오른쪽 위에 항상 떠 있는
판 하나가 전부이며, 5분마다 스스로 값을 새로 읽어 옵니다.

이 문서는 **실행파일(exe)로 쓰는 방법**만 다룹니다. 크롬 확장과 북마클릿으로 쓰는
방법은 [[README]]에 있습니다.

---

## 1. 설치

설치 과정이 따로 없습니다. 폴더를 통째로 옮겨 두고 실행파일을 누르면 됩니다.

1. `EIS 근무시간 위젯-win32-x64` 폴더를 원하는 자리에 복사합니다.
   (예: `C:\Users\<사번>\Apps\EIS 근무시간 위젯-win32-x64`)
2. 폴더 안의 **`EIS 근무시간 위젯.exe`** 를 실행합니다.
3. 자주 쓸 것이므로, 그 실행파일을 오른쪽 클릭하여 **작업 표시줄에 고정**하거나
   바탕화면 바로 가기를 만들어 두면 편합니다.

Node.js를 따로 설치할 필요가 없습니다. 필요한 실행 환경이 폴더 안에 모두 들어 있습니다.
폴더 크기는 약 367MB이며, 그중 대부분이 Electron 실행 환경입니다.

> **폴더째로 옮겨야 합니다.** 실행파일 하나만 떼어 내면 옆에 있는 `resources` 폴더와
> DLL들을 찾지 못해 실행되지 않습니다.

## 2. 처음 켤 때 — 로그인은 직접 하셔야 합니다

앱을 켜면 그룹웨어 로그인 창이 먼저 뜹니다. 여기서 두 가지를 하셔야 합니다.

1. 평소처럼 **아이디와 비밀번호로 로그인**합니다.
2. 로그인한 뒤, 평소처럼 **근무시간현황 메뉴까지 눌러서 이동**합니다.

근무시간 화면이 뜨는 순간 그 창은 스스로 숨고, 화면 오른쪽 위에 위젯이 나타납니다.
그 뒤로는 앱이 숨은 창에서 알아서 값을 읽어 오므로 브라우저를 켤 일이 없습니다.

> **로그인만 하고 멈추면 값이 들어오지 않습니다.** EIS 쪽 세션은 포털에서 메뉴를 눌러
> 넘어가는 그 동작이 만들어 냅니다. 주소만 직접 불러서는 세션이 만들어지지 않는다는
> 것을 2026-09-07에 세 차례 확인했습니다. 그래서 앱은 포털 화면에서 기다리기만 하고,
> 메뉴를 누르는 일은 사람이 합니다.

> **앱을 끄면 로그인 상태가 사라집니다.** 그룹웨어와 SSO가 발급하는 쿠키에 만료 시각이
> 적혀 있지 않아, 앱이 종료될 때 쿠키도 함께 없어지기 때문입니다 (2026-09-04 실측,
> 3회 반복 확인). 따라서 앱을 켤 때마다 로그인 창이 한 번 뜨고, 그 뒤로는 조용히
> 돌아갑니다. 하루에 한 번 로그인한다고 생각하시면 됩니다.

## 3. 화면 읽는 법

위젯은 세로 선으로 나뉜 **세 칸**으로 이루어져 있습니다. 왼쪽부터 차례로 달성률,
잔여 시간, 오늘의 기록입니다.

```
┌──────────────────┬──────────────────────────┬────────────────────────────┐
│ 달성률 ·         │ 잔여 시간                │ 오늘 · 09-08               │
│ 출장·휴일 포함   │                          │                            │
│                  │ 남은시간       9:58 남음 │ 출근 / 퇴근      08:13 / – │
│    ◜◝  88 %      │ 출장·휴일 포함           │ 근무 · 현재까지     38:02  │
│                  │ ────────────────────     │ 출근예정  24:00 (+휴일 8:00)│
│  현재까지 48%    │ 현재까지      41:58 남음 │ 기준 근무           80:00  │
│                  │ ────────────────────     │                            │
│                  │ 이 중 휴일근무      8:00 │ 정산기간 08-30 ~ 09-12 ·   │
│                  │                          │ 18회차                     │
└──────────────────┴──────────────────────────┴────────────────────────────┘
```

### 첫째 칸 — 달성률

기준 근무시간을 얼마나 채웠는지를 백분율로 나타냅니다.

| 표시 | 뜻 | 계산 |
|---|---|---|
| **반원 계기** | 진한 호가 지금까지 채운 몫, 그 뒤에 이어지는 옅은 호가 앞으로 채울 몫입니다 | 진한 호 = 현재까지 달성률, 옅은 호 = 출근예정과 휴일근무 예정을 더했을 때 늘어나는 만큼 |
| **큰 숫자 (88%)** | 앞으로 잡혀 있는 **출근예정과 휴일근무까지 모두 채웠다고 볼 때**의 달성률입니다 | (현재까지 근무 + 출근예정 + 휴일근무 예정) ÷ 기준 근무 |
| **현재까지 48%** | 지금까지 실제로 찍힌 근무만으로 계산한 달성률입니다 | 현재까지 근무 ÷ 기준 근무 |

> **큰 숫자와 둘째 칸의 `남은시간`은 같은 사실을 다르게 적은 것입니다.** 둘 다 출근예정과
> 휴일근무까지 반영하므로, 큰 숫자가 100%를 넘는 순간 `남은시간`이 빨간색 `초과`로
> 바뀝니다. 한쪽만 보셔도 됩니다.

### 둘째 칸 — 잔여 시간

정산기간을 마칠 때까지 얼마가 남았는지를 시간과 분으로 나타냅니다. 이 위젯을 만든
목적이 바로 이 칸입니다.

| 표시 | 뜻 | 계산 |
|---|---|---|
| **남은시간** (출장·휴일 포함) | 앞으로 잡혀 있는 출근예정과 휴일근무까지 모두 반영한 잔여입니다. 정산기간이 끝났을 때 최종으로 남을 시간이라고 보시면 됩니다 | 기준 근무 − 현재까지 근무 − 출근예정 − 휴일근무 예정 |
| **막대 (위)** | 진한 부분이 현재까지 채운 몫, 옅은 부분이 예정으로 채울 몫입니다 | 위 두 값을 기준 근무에 대한 비율로 그린 것입니다 |
| **현재까지** | 지금까지 찍힌 근무만 반영한 잔여입니다. 앞으로의 예정이 빠져 있으므로 항상 위쪽 값보다 큽니다 | 기준 근무 − 현재까지 근무 |
| **막대 (아래)** | 현재까지 채운 몫만 그립니다 | 현재까지 달성률 |
| **이 중 휴일근무** | 위쪽 `남은시간`에 반영되어 있는 휴일근무 예정분입니다. 예정이 없으면 `휴일근무 예정 없음`으로 바뀝니다 | 오늘 이후 행의 휴일근무 합계 |

**색과 낱말이 방향을 알려 줍니다.**

- **파란색 + `남음`**: 아직 채워야 할 시간이 남아 있습니다.
- **빨간색 + `초과`**: 기준 근무를 이미 넘겼습니다. 숫자 앞에 붙은 `-`도 같은 뜻입니다.

### 셋째 칸 — 오늘

오늘 하루의 기록과 정산기간의 기준값을 모아 둔 칸입니다.

| 표시 | 뜻 |
|---|---|
| **오늘 · 09-08** | 오늘 날짜입니다. 그 오른쪽에 경고가 붙는 경우는 아래 4절을 보십시오 |
| **출근 / 퇴근** | 오늘 찍힌 출근 시각입니다. 퇴근 자리는 **언제나 `–`로 비워 둡니다** |
| **근무 · 현재까지** | 정산기간이 시작된 뒤 오늘까지 실제로 인정된 근무시간의 합계입니다 |
| **출근예정** | 오늘 이후에 잡혀 있는 근무 예정입니다. 괄호 안의 `(+휴일 8:00)`은 그와 별도로 잡힌 휴일근무 예정분입니다 |
| **기준 근무** | 이 정산기간에 채워야 하는 시간입니다 (2주 기준 80:00) |
| **정산기간** | 기간의 시작일과 종료일, 그리고 회차입니다 |

> **퇴근 자리를 비워 두는 이유가 있습니다.** EIS 화면에서 오늘 행의 종료시간 칸은
> 퇴근 시각이 아니라 **조회한 시점**을 담고 있습니다. 2026-09-07에 6분을 흘려 보내며
> 확인한 결과, 그 칸도 6분 뒤로 밀렸고 근무시간도 정확히 6분 늘었습니다. 그대로
> 보여 주면 퇴근한 것처럼 읽히므로 비워 둡니다.

### 시간 표기

`38:02`는 38시간 2분입니다. 시간과 분을 콜론으로 나눈 표기이며, 시각이 아닙니다.

EIS 화면은 근무시간을 시간 단위로 잘라서 보여 줍니다(예: 잔여 `-12`). 위젯은 같은
화면에 들어 있는 **분 단위 원본**을 읽으므로 `-11:24`처럼 분까지 맞습니다. 화면의
`-12`는 이 값을 내림한 것입니다.

## 4. 조작

### 위젯 창의 단추

오른쪽 위에 두 개가 있습니다.

| 단추 | 하는 일 |
|---|---|
| **⟳** | 5분을 기다리지 않고 곧바로 다시 읽습니다 |
| **✕** | 위젯 창을 닫습니다. 트레이 메뉴에서 다시 켤 수 있습니다 |

창은 **끌어서 옮길 수 있고, 옮긴 자리를 기억합니다.**

### 트레이 아이콘

작업 표시줄 오른쪽 끝 알림 영역에 아이콘이 상주합니다. 아이콘 자체가 현재 달성률을
호로 그려 보여 주므로, 위젯을 닫아 두었을 때도 대략을 알 수 있습니다.

- **아이콘을 한 번 누르면** 위젯 창이 켜지고 꺼집니다.
- **마우스를 올리면** 잔여와 달성률, 마지막으로 읽은 시각이 풍선말로 뜹니다.
- **오른쪽 클릭**하면 메뉴가 나옵니다.

| 메뉴 항목 | 하는 일 |
|---|---|
| 잔여 … (맨 위, 누를 수 없음) | 지금 값을 요약해 보여 줍니다 |
| 위젯 창 보이기 | 표시 창을 켜고 끕니다 |
| 지금 새로 읽기 | 곧바로 다시 읽습니다 |
| EIS 화면 열기 | 숨어 있던 수집 창을 띄웁니다. 값이 이상할 때 원본을 눈으로 확인하는 용도입니다 |
| 종료 | 앱을 끝냅니다 |

**✕로 창을 닫아도 앱은 살아 있습니다.** 완전히 끄시려면 트레이 메뉴의 `종료`를
쓰십시오.

## 5. 값이 안 보일 때

### 위젯에 경고가 붙은 경우

| 경고 | 뜻 | 대처 |
|---|---|---|
| **n분 전 값** (테두리가 점선이 되고 전체가 흐려집니다) | 지금 값을 읽지 못해 마지막으로 읽은 값을 그대로 띄우고 있습니다 | 로그인이 풀린 경우가 대부분입니다. 트레이 메뉴의 `EIS 화면 열기`로 창을 띄우고 다시 로그인하십시오 |
| **출근예정이 더 있을 수 있음** | EIS 표가 잘려서 아래쪽 예정 행을 다 읽지 못했을 가능성이 있습니다 | `남은시간` 값이 실제보다 크게 나올 수 있습니다. EIS 화면에서 직접 확인하십시오 |

### 위젯이 아예 안 뜨는 경우

**그것도 정상 동작입니다.** EIS 화면 구조가 바뀌면 값을 잘못 읽는 대신 아무것도 그리지
않도록 만들었습니다. 조용히 틀린 숫자를 보여 주는 쪽이 훨씬 위험하기 때문입니다.

1. 로그인 창이 떠 있다면 로그인하고 근무시간현황 메뉴까지 눌렀는지 확인하십시오 (2절).
2. 트레이 메뉴의 `EIS 화면 열기`로 수집 창을 띄워 화면이 제대로 그려지는지 보십시오.
3. 그래도 안 되면 EIS 화면이 개편된 것이므로 위젯을 고쳐야 합니다.

### 진단 기록

앱이 하는 일은 아래 파일에 그대로 남습니다. 문제를 알릴 때 이 파일을 함께 보내
주시면 원인을 찾기 쉽습니다.

```
%APPDATA%\eis-work-widget\run.log
```

주소창이나 탐색기 주소 칸에 위 경로를 그대로 붙여 넣으면 열립니다.

## 6. 이 앱이 하는 일과 하지 않는 일

- **화면에 이미 그려진 숫자만 읽습니다.** 서버에 따로 요청하지 않고, 숨은 내부 객체를
  뒤지지 않으며, 트랜잭션을 직접 부르지도 않습니다. 사람이 눈으로 보는 것과 같은 값을
  같은 자리에서 읽을 뿐입니다.
- 딱 한 번 **오늘 날짜 행을 클릭**합니다. 출퇴근 시각을 얻기 위해서이며, 사람이 하는
  클릭과 같습니다. 일별 상세가 이미 오늘을 가리키고 있으면 클릭하지 않습니다.
- **로그인은 언제나 사용자가 직접 합니다.** 앱은 아이디와 비밀번호를 다루지 않고,
  저장하지도 않습니다.
- 읽은 값은 **이 컴퓨터 안에만** 남습니다. 어디로도 보내지 않습니다.

이 컴퓨터에 남는 것은 다음 두 가지뿐입니다.

| 파일 | 내용 |
|---|---|
| `%APPDATA%\eis-work-widget\settings.json` | 위젯 창의 위치, 창을 켜 둘지 여부, 로그인한 적이 있는지 여부 |
| `%APPDATA%\eis-work-widget\run.log` | 앱이 무엇을 했는지에 대한 기록 (실행할 때마다 새로 씁니다) |

앱을 지우실 때는 폴더를 지우고 위 `%APPDATA%\eis-work-widget` 폴더를 함께 지우면
흔적이 남지 않습니다.

## 7. 실행파일을 다시 만들 때 (개발자용)

표시 내용을 고쳤다면 실행파일을 다시 만들어야 반영됩니다. `widget-core.js`는 앱을
켤 때 한 번만 읽히기 때문입니다.

```bash
node build.js && node verify-bookmarklet.js
```

위 검사를 모두 통과한 뒤, `desktop` 폴더에서 아래를 실행합니다.

```bash
npm.cmd run package
```

산출물은 `dist\EIS 근무시간 위젯-win32-x64\`에 만들어집니다.

> PowerShell에서 `npm`이 실행 정책에 막히면(`npm.ps1 파일을 로드할 수 없습니다`)
> `npm` 대신 **`npm.cmd`** 를 쓰십시오. 실행 정책 자체를 바꾸지 않고 넘어갈 수 있습니다.

고칠 때의 자세한 규칙은 [[README]]의 "고칠 때" 절에 있습니다.
