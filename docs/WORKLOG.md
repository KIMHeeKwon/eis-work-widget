# WORKLOG — EIS 근무시간 위젯

## 2026-09-04

### 목표

사내 통합경영정보시스템(EIS)의 근무시간현황 화면을 매번 열어 보지 않아도
출퇴근 기록과 잔여 근무시간을 한눈에 확인할 수 있는 위젯을 만든다.

### 결정사항

- **디자인은 A안(계기 + 3칸, 592×132)으로 확정한다.** 달성률을 반원 계기 하나로
  보여 주고, 나머지를 잔여 시간과 오늘 기록 두 칸에 나눈다. 토큰은
  `Design/design_handoff_usage_monitor_widget/`의 Industry 라이트 테마를 그대로 쓴다.
- **주소를 배포물에 넣지 않는다.** `@match https://<사내 EIS 도메인>/*`로 도메인만
  잡고, 근무시간현황 화면이 뜨면 스스로 알아차려 붙는다. 팀원과 나눠 쓸 때
  특정 화면 주소가 배포물에 남지 않는다.
- **보안 우회를 하지 않는다** (사용자 지시). Nexacro 내부 객체를 뒤지거나 트랜잭션을
  직접 부르지 않고, 화면에 이미 표시된 값만 읽는다. 위젯이 대신 하는 조작은
  오늘 날짜 행 클릭 한 번뿐이고, 일별 상세가 이미 오늘을 가리키면 그마저 하지 않는다.
- **문구**: '실적' 대신 '현재까지', '계획' 대신 '출근예정 포함'을 쓴다 (사용자 요청).

### 산출물

- `eis-work-widget.user.js` — 위젯 본체 (Tampermonkey 유저스크립트)
- `widget-mockups.html` — 예시안 4종. A안이 채택됐고 문구 변경까지 반영했다.
- `docs/WORKLOG.md` — 이 문서

### 핵심 발견 (2026-09-04 실측, 회의용 계정 1개·정산기간 1건 기준)

1. **분이 사라지는 문제의 원천 해결.** EIS 화면은 기준·실·잔여 근무시간을 시간
   단위로 잘라 보여 준다(80 / 68 / −12). 잔여 −12는 실제 −11:24를 내림한 값이라
   36분이 소실된다. 그런데 **같은 화면에 분 단위 원본이 이미 들어 있다.**

   | 값 | 컴포넌트 ID(끝부분) | 실측 |
   |---|---|---|
   | 기준근무시간(분) | `switch1.case1.form.output10:input` | 4800 = 80:00 |
   | 실근무시간(분) | `switch1.case1.form.output9:input` | 4116 = 68:36 |

2. **가상 스크롤을 우회할 필요가 없다.** `output9`는 출근예정까지 더한 전체 합계다.
   목록이 날짜 내림차순이라 미래 날짜 행은 언제나 맨 위에 그려지므로, 그 합을 빼면
   지금까지의 실적이 나온다. `4116 − 1920 = 2196분 = 36:36`으로 검산됐다.
   마지막으로 그려진 행까지 미래 날짜이면 안 보이는 계획이 더 있을 수 있으므로
   위젯이 "출근예정이 더 있을 수 있음"을 띄운다.

3. **Nexacro가 전역으로 `div { position:absolute; overflow:hidden }`을 건다.**
   그대로 두면 위젯의 자식이 흐름에서 빠져나가 부모가 **높이 2px로 접힌다.**
   `#eisw *{position:static;overflow:visible;…}` 리셋을 스타일 맨 앞에 두어 해결했다.
   리셋을 떼면 다시 2px가 되는 것까지 화면에서 확인했다.

4. **셀 파싱은 좌표로 한다.** Nexacro는 셀을 절대 좌표에 놓아 표 구조가 DOM 계층에
   없다. leaf `.nexacontentsbox`를 모아 y로 행을 묶고, 머리글 셀의 x를 기준점 삼아
   가장 가까운 열 이름을 붙인다. 열 순서가 바뀌어도 견딘다.

### 검증 결과 (2026-09-04, 정산기간 2026-08-30 ~ 09-12 18회차 1건)

| 항목 | 값 |
|---|---|
| 기준 근무 | 80:00 |
| 근무 · 현재까지 | 36:36 |
| 출근예정 | 24:00 (+휴일 8:00) |
| 잔여 · 현재까지 | 43:24 |
| 잔여 · 출근예정 포함 | 19:24 |
| 휴일까지 반영 시 | 11:24 |
| 달성률 | 46% / 출근예정 포함 76% |
| 오늘 출퇴근 | 08:13 ~ 08:17 |

화면에 얹어 592×162로 렌더링되는 것과 위 값이 모두 맞는 것을 확인했다.
설계상 높이는 132였으나 Barlow가 설치되지 않은 환경의 대체 글꼴 때문에 30px 커졌다.

### 남은 미해결

- **Tampermonkey 설치 가능 여부 미확인.** 브라우저 도구로는 확장 설치 정책을 볼 수
  없다. 막혀 있으면 같은 코드를 북마클릿으로 전환할 수 있다.
- **표본이 정산기간 1건뿐이다.** 특히 정산기간 첫날처럼 계획 행이 10개에 이르는
  경우, 화면에 8행만 그려져 계획이 잘릴 수 있다. 위젯은 그 상황을 감지해 경고를
  띄우지만, 실제로 그런 기간에서 확인한 적은 없다.
- 휴일근무가 여러 날 잡힌 경우, 연장·야간 열이 채워진 경우를 확인하지 못했다.

### 다음 단계

1. 사용자가 Tampermonkey에 설치해 다른 날짜·다른 정산기간에서 확인한다.
2. 확장 설치가 막혀 있으면 북마클릿판을 만든다.
3. 팀 배포 시 화면 구조가 바뀌면 값이 안 나오므로, 그때는 조용히 틀린 값을 내지 않고
   위젯이 뜨지 않도록 되어 있음을 안내한다.

## 2026-09-04 (이어서) — 북마클릿 배포 경로와 배포 문서

### 목표

Tampermonkey 설치 가능 여부가 확인되지 않은 상태에서 막히지 않도록, 확장 없이 쓰는 경로를
미리 만들어 두고 팀에 나눠 줄 안내 문서를 쓴다.

### 결정사항

- **북마클릿은 손으로 만들지 않고 유저스크립트에서 뽑아낸다.** 두 벌을 손으로 관리하면 반드시
  어긋난다. `eis-work-widget.user.js`가 단일 원천이고, `build-bookmarklet.js`가 파생본을 만든다.
- **줄 전체가 주석인 줄만 지우고 개행은 남긴다.** 줄을 이어 붙이면 세미콜론이 없는 자리에서
  자동 세미콜론 삽입이 엉뚱하게 동작할 수 있는데, 22KB를 줄이자고 감수할 위험이 아니다.
- **빌드 검사와 실행 검사를 나눈다.** 문법·인코딩은 빌드가 보고, "실제로 도는가"는 별도
  스크립트가 본다. 앞의 것만으로는 주석 제거가 코드 의미를 바꿨는지 알 수 없다.

### 산출물

| 파일 | 내용 |
|---|---|
| `build-bookmarklet.js` | 머리말·주석 제거 → `new Function()` 문법 검사 → URL 인코딩 → 왕복 확인 → 핵심 조각 존재 확인 |
| `eis-work-widget.bookmarklet.txt` | 빌드 산출물 (22,828자) |
| `verify-bookmarklet.js` | 뽑아낸 북마클릿을 Node의 최소 DOM 스텁 위에서 실제로 실행 |
| `README.md` | 팀 배포용 설치·사용 안내 (Tampermonkey / 북마클릿 두 갈래) |

`eis-work-widget.user.js`에는 타이머 중복 가드 한 줄을 더했다 — 북마클릿은 여러 번 눌릴 수 있다.

```javascript
if (window.__eiswTimer) clearInterval(window.__eiswTimer);
window.__eiswTimer = setInterval(tick, 1500);
```

### 검증 결과 (2026-09-04 실행)

빌드: `원본 19,461 bytes / 코드 14,189 bytes (문법 검사 통과) / 북마클릿 22,828 chars`.
제거된 줄 전체 주석 36개.

실행 검사 통과 항목:

- IIFE가 예외 없이 끝까지 돌고 타이머를 등록한다
- EIS 화면이 아니고 캐시도 없으면 **아무것도 그리지 않는다**
- 캐시가 있으면 "n분 전 값" 화면을 그리고, 값이 전부 맞다
  (`43:24` · `19:24` · `11:24` · `08:13` / `08:17` · `12분 전 값` · `46%` / `76%`)

**"n분 전 값" 경로는 이번에 처음 확인했다.** 실제 EIS 화면에서는 다른 메뉴로 옮겨 가야
재현되는 경로라 그동안 눈으로 본 적이 없었다.

### 이번에 실패한 접근 (기록)

브라우저에서 북마클릿을 직접 실행해 보려 했으나 세 갈래가 다 막혔다 —
① 크롬 확장이 `file://`을 열지 못하고(`https://file:///...`로 망가진다),
② 로컬 정적 서버 기동이 권한 거부됐고,
③ 앱 내 브라우저는 프로젝트 폴더 밖 파일을 정적 스냅샷으로만 연다.
그래서 Node에 최소 DOM 스텁을 두는 쪽으로 돌렸고, 결과적으로 **회귀 검사로 남길 수 있는**
자동 검증이 되어 브라우저에서 한 번 눈으로 보는 것보다 나은 산물이 됐다.

### 남은 미해결

- 북마클릿을 **실제 크롬 북마크바에 등록해** 누르는 것은 사용자만 할 수 있다 (확장 설치 가능
  여부도 함께 확인 필요).
- 표본이 여전히 정산기간 1건이다. 예정 행이 많아 표가 잘리는 기간, 휴일근무 복수일,
  연장·야간 열이 채워진 경우는 겪지 못했다.

### 다음 단계

1. 사용자가 A안(Tampermonkey) 또는 B안(북마클릿)으로 설치해 며칠 써 본다.
2. 다른 정산기간에서 값이 어긋나면 그 화면의 그리드 행을 그대로 받아 파싱 규칙을 고친다.

### 2026-09-04 (이어서) — 실제 EIS 화면에서 위젯 동작 확인

- **목표**: Tampermonkey가 스크립트를 실행하지 않는 문제로 막혀 있어, 코드를 EIS 탭에 직접
  넣어 위젯이 실제 화면에서 제대로 도는지부터 확인한다.
- **수행**: `eis-work-widget.bookmarklet.txt`를 디코딩한 코드 전문(14,189 bytes)을 EIS 탭
  (근무시간현황 화면)에 주입하고, `getBoundingClientRect()`와 `innerText`로 결과를 읽었다.
- **결과 (2026-09-04 실측, 정산기간 08-30 ~ 09-12 18회차 — 표본 1건)**:
  크기 592 × 162 (Nexacro 전역 CSS에 눌리지 않음), 타이머 등록됨, `stale` 아님.
  달성률 47% / 출근예정 포함 77%, 잔여 현재까지 42:10, 출근예정 포함 18:10,
  휴일 8:00 반영 시 10:10, 오늘 08:13 ~ 09:31, 근무 37:50, 출근예정 24:00 (+휴일 8:00),
  기준 80:00. 오늘 행 클릭으로 출퇴근 시각을 얻는 경로도 실제 화면에서 동작했다.
- **의의**: 그동안의 검증은 Node 스텁(캐시 재생) 한정이었다. **실제 Nexacro 화면에서
  셀 좌표 파싱·오늘 행 클릭·계산·렌더링이 끝까지 도는 것을 처음 확인했다.**
- **남은 미해결**: ① Tampermonkey 미실행 원인 미규명 (확장 팝업·대시보드 확인 필요 —
  사용자 몫). ② 주입 방식은 새로 고침으로 사라지므로 항구 사용에는 북마클릿 등록이 필요하다.
- **다음 단계**: 북마클릿 등록을 권한다. 확장 설정과 무관하게 동작하고 등록은 1회로 끝난다.

### 2026-09-04 (이어서) — 크롬 확장으로 배포 경로 전환

- **문제**: Tampermonkey가 크롬 152에서 스크립트를 실행하지 않았고(확장별 "사용자 스크립트
  허용" 토글을 켠 뒤에도 동일), 대안으로 안내한 북마클릿은 22,828자를 손으로 복사·붙여넣는
  방식이라 사용자가 "너무 원시적"이라고 지적했다. **막힌 도구를 붙잡는 대신 그 제약을 아예
  받지 않는 경로로 바꾸는 것이 옳았다.**
- **결정**: MV3 크롬 확장(압축해제 로드)으로 간다. 일반 content script이므로 사용자 스크립트
  권한 토글과 무관하고, 복사·붙여넣기가 없으며, 팀원 배포는 폴더 전달로 끝난다.
- **산출물**:
  - `extension/manifest.json` — `permissions` 항목 없음, `content_scripts.matches`는
    `https://<사내 EIS 도메인>/*` 하나. 요구 권한 0.
  - `extension/widget.js` — 생성물(19,177 bytes). 직접 고치지 않는다.
  - `build-bookmarklet.js` → `build.js`로 이름을 바꾸고 확장 산출 단계를 추가했다. 유저스크립트
    하나에서 확장·북마클릿 두 벌이 함께 나오므로 손으로 관리하는 사본이 늘지 않는다.
  - `README.md` — 설치 A안을 크롬 확장으로 교체, Tampermonkey는 권하지 않는 이유와 함께 각주로 이관.
- **검증 (2026-09-04 실측)**: 확장 설치 후 EIS 새로 고침만으로 위젯이 자동 표시됐다.
  592 × 162, `stale` 아님, 값 갱신 확인(09:31 → 09:43로 근무 37:50 → 38:02). 격리된 world라
  페이지 쪽 `window.__eiswTimer`는 보이지 않으며(정상), 판정은 페이지 DOM의 `#eisw`로 한다.
  `node build.js && node verify-bookmarklet.js` 전 항목 통과.
- **교훈 (#tooling)**: 확장 프레임워크(Tampermonkey)를 쓰는 이유는 편의였는데, 그 편의가
  플랫폼 정책 변화로 사라지자 오히려 진입 장벽이 됐다. **content script 두 파일이면 되는 일에
  중간 계층을 둔 것이 원인이었다.**
- **남은 미해결**: 개발자 모드 확장은 크롬 재시작 시 경고 풍선이 뜬다(동작에는 지장 없음).
  조직 정책으로 개발자 모드가 막힌 PC에서는 B안(북마클릿)으로 간다. 다른 정산기간 검증은 계속 미해결.

## 2026-09-04 (오후) — 데스크톱 앱 전환과 EIS 세션 입구 규명

- **목표**: 브라우저 안이 아니라 PC에서 상주하는 위젯으로 바꾸고, 위젯이 스스로 EIS에
  접속해 값을 읽게 한다.
- **형태 결정**: 트레이 상주 + 항상 위에 뜨는 작은 창(옵션으로 전환). Electron으로 만들고,
  숨김 수집 창이 EIS 화면을 읽어 표시 창으로 값을 보낸다. 파싱·계산·렌더는
  [[eis-work-widget.user.js]] 하나가 그대로 단일 원천이며, `build.js`가 데스크톱용 사본을 낸다.
- **핵심 발견 — EIS 세션을 만드는 입구** (2026-09-04 실측, 사용자가 포털에서 직접 이동한

### 결정사항 (사용자 선택)

- **도메인은 지우지 않고 `<사내 EIS 도메인>`이라는 자리표시자로 바꾼다.** 통째로
  지우면 README의 접속 방식 설명과 WORKLOG의 실측 근거가 함께 사라진다. 자리표시자로
  두면 소속은 감추면서 기술 서술은 그대로 읽힌다.
- **`docs/보안검토_요청서.md`는 저장소에서 빼고 따로 보관한다.** 사내 보안팀에
  제출하려고 쓴 문서라서 소속과 작성자를 지우면 문서의 목적 자체가 사라진다. 원본은
  온전한 채로 프로젝트 폴더 밖에 두었다.
- **실행파일의 저작권 표시(`--app-copyright="ETRI"`)는 그대로 둔다.** 문서가 아니므로
  이번 정리 범위 밖이다.

### 곁들여 바로잡은 것 — 사실과 어긋난 경고 문구

여러 문서에 "사내 시스템 주소가 문서에 적혀 있으므로 외부에 올리지 말 것"이라고
적혀 있었는데, **`USAGE.md`와 `읽어보세요.md`에는 주소가 한 줄도 없었다.** 경고의
사유가 틀렸던 것이다. 경고 자체는 유효하므로 유지하되, 사유를 실제에 맞게
"사내 시스템에 접속하도록 만든 프로그램이고 실행파일 안의 코드에 사내 주소가 들어
있다"로 고쳤다. 같은 문구가 릴리스 본문에도 있어 함께 고쳤다.

### 산출물

- `README.md`, `docs/WORKLOG.md` — 도메인 4곳을 자리표시자로, 소속 표현 3곳을 일반
  표현으로 바꿨다.
- `docs/보안검토_요청서.md` — 저장소에서 제거했다.
- `전달용/읽어보세요.md` — 경고 사유를 바로잡았다.
- 발행한 릴리스 `v1.1.0` — 본문을 고쳐 다시 올렸고, 첨부 문서 두 개도 갱신본으로
  덮어썼다. 실행파일 꾸러미는 손대지 않았다.

### 남은 미해결

- **`dist` 폴더를 아직 못 지웠다.** Claude 데스크톱 앱을 끈 뒤 지우면 된다.
- **`전달용/` 폴더에 잔여물이 남아 있다** — `근무시간_위젯.zip`과 `데스크톱앱/` 폴더.
- 팀원 공유 방식(보안 검토 결과 대기), `run.log` 기록 여부, 닫기 단추가 다음 실행까지
  이어지는 동작, 다른 정산기간 검증 — 계속 대기.
